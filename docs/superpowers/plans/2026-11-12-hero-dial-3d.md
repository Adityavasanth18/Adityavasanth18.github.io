# Hero Dial 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render the hero's project dial as a solid, lit 3D brass instrument without changing anything else on the site.

**Architecture:** A WebGL canvas sits *behind* the existing `.project-atlas` (as its previous sibling inside `.folio-atlas-wrap`). The Three.js scene is built in CSS-pixel units with a camera that reproduces the CSS perspective already applied to `.project-atlas` by `motion.js` (`transformPerspective: 1100`), and every frame it copies that element's GSAP transform (rotationX/Y, rotation, scale, y, opacity). The 3D instrument's top face therefore coincides with the tilted HTML layer, so the existing buttons, centre text, sector arcs and focus ray stay the real controls and stay registered on the metal. Only the flat SVG base artwork is hidden, and only after the first 3D frame.

**Tech Stack:** Three.js 0.187.0 (ES module, vendored), existing GSAP 3.15 + ScrollTrigger, Playwright (Python) for checks. No build step.

**Spec:** `docs/superpowers/specs/2026-11-12-hero-dial-3d-design.md`

## Global Constraints

- No new colour. Materials, lights and environment are tinted only from: `#d7ae78`, `#e0b87e`, `#c49a67`, `#1c1916`, `#221f1b`, `#2f2820`, `#49372a`, `#f0ddba`, and the patina colours `#e0b87e` (agents), `#d58b5f` (systems), `#8fb59c` (search), `#bdb5a2` (products).
- No edits to text content, `styles.css`, `folio.css`, `upscale.css`, `sharpen.css`, `app.js`, `guilloche.js`, `essays/`, `work/`.
- `motion.js` may be touched only if Task 3 proves it necessary; prefer zero edits.
- Fallback (flat dial exactly as today) when any holds: `prefers-reduced-motion: reduce`; not `(hover: hover) and (pointer: fine)`; viewport `< 900px`; no WebGL2; `window.__motion` not set within 4s; any error during setup.
- Three.js is fetched only when the fallback conditions do not hold.
- Libraries are vendored under `assets/vendor/`.
- Branch `dial-3d`; nothing merged to `main`.

## Review Focus

1. WebGL context lost mid-session → flat dial comes back, no blank hole.
2. Window resized across 900px or dial resized → canvas and camera re-fit; below 900px the flat dial returns.
3. Tab hidden / hero scrolled away → rendering stops (no background GPU use).
4. Project filtered/selected by keyboard → 3D pointer follows the same node.
5. Slow connection: Three.js still loading → flat dial is visible and usable the whole time.

## File Structure

- Create `assets/vendor/three.module.min.js`, `assets/vendor/three.core.min.js` (unmodified from npm `three@0.187.0/build/`), `assets/vendor/THREE-LICENSE.txt`.
- Create `assets/dial3d.js`: ES module. Gate, lazy import, scene, sync loop. Single responsibility: the 3D dial.
- Create `assets/dial3d.css`: canvas placement and the `.has-dial3d` rules that hide the flat SVG base.
- Modify `index.html`: one `<link>` and one `<script type="module">`.
- Create `tests/dial3d_check.py`: Playwright checks (not deployed concern; small).

### Task 2: The instrument

**Files:** Modify `assets/dial3d.js`, `assets/dial3d.css`.

**Interfaces:**
- Consumes: canvas + gate from Task 1.
- Produces: `build(THREE, { canvas, atlas, wrap }) -> { render(), resize(), setSelected(index, colorHex), dispose(), group }` where `group` is the instrument root at the dial-plane origin.

- [ ] **Step 1: Camera and units.** Scene unit = 1 CSS px; origin = centre of `.project-atlas`; +y up. Canvas covers the atlas box plus 14% margin per side. `PerspectiveCamera` at `z = 1100`, `fov = 2·atan(canvasCssHeight / 2 / 1100)`. `devicePixelRatio` capped at 2.
- [ ] **Step 2: Geometry** (all scaled by `s = atlasWidth / 600`, matching the SVG's 600 viewBox; top face at `z = 0`, body behind it):
  - base plate: lathe profile, radius 282, depth 26, bevelled rim;
  - raised rings at radii 282, 250, 196, 118 (the SVG's rings), height ≤ 6, bevelled;
  - 120 tick marks at radius 258–276 (every 5th longer), instanced;
  - central rosette boss under the title area, low relief so text stays readable;
  - 24 studs at the button positions (read each button's `left/top` %), height 4;
  - one pointer arm from centre to the selected stud.
- [ ] **Step 3: Materials and light.** `MeshStandardMaterial`, metalness 1, roughness 0.32–0.55, colours from the palette only (plate `#2f2820`→`#49372a`, rings/ticks `#c49a67`, studs `#d7ae78`, pointer = selected category patina). Environment: a `PMREMGenerator` render of a tiny in-code scene of emissive panels coloured `#f0ddba`, `#d7ae78`, `#49372a` on `#1c1916`. One key `DirectionalLight` `#f0ddba`, one rim light `#d7ae78`. Renderer `alpha: true`, `ACESFilmic` off (`NoToneMapping`) so palette colours are not shifted, `outputColorSpace = SRGBColorSpace`.
- [ ] **Step 4: `.has-dial3d` CSS**: hide the SVG's base disc, tick group and petals (`.atlas-geometry > circle:first-of-type`, the stroke group, `.atlas-petals`); keep `.atlas-sectors`, `.atlas-focus-ray` hidden→replaced by 3D pointer, node buttons and centre text visible. Class is added after the first successful `render()`.
- [ ] **Step 5: Run checks** → `desktop_ready`, `canvas_painted` PASS. Screenshot and look at it; iterate on proportions until it reads as engraved brass.
- [ ] **Step 6: Palette test.** Add `palette_only` to the check script: sample 400 opaque canvas pixels; every pixel's hue must fall in the bronze band (15°–50°) or have saturation < 0.12, except within the pointer/sector region. Run → PASS.
- [ ] **Step 7: Commit.**
